Every finding is listed individually in the report with its id, file, severity, fix and

**The HIGH finding.** `02a02675` — a token-transfer replay vector on the deposit
money-path in `vault_adapter.rs`: `env.authorize_as_current_contract` entries are not
single-use, so a malicious vault could match one pre-authorised transfer repeatedly and
drain the pool's existing BLEND balance. It is fixed with a balance-delta guard, covered
by a regression test, and reported validated on testnet. All five MEDIUM findings are
fixed.

**A methodological result worth reading.** Scout's first run on this workspace reported
zero findings on both crates *and exited 0* while never having compiled or linted them —
a transient network failure in its `dylint_driver` build script produced a false
all-clear. Any CI integration of Scout must assert on the `Checking vaquita-*` lines or a
non-zero detector count rather than trusting the exit code, or a network blip silently
turns the security gate green. This is recorded as open item **O7**.
