## 2. The flow

Four legs, covered by the recording in a single pass:

1. **Fiat in.** The user funds an Anclap account in ARS (or USD) and initiates a SEP-24
   interactive deposit from the Vaquita web app.
2. **KYC.** Anclap's hosted interactive flow collects and verifies identity data, in
   Spanish.
3. **Settlement to USDC.** Anclap settles to USDC on the Stellar public network, issued by
   Circle (`GA5ZSEJYB37JRC5AVCIA5MOP4RHTM335X2KGX3IHOJAPP5RE34K4KZVN`).
4. **Deposit into the vault.** The user deposits that USDC into `vaquita-pool`
   (`CDTTAZ3NK4MMDHK2C3I6LRDT4YADJZ2QXINKLKQNZUVX7OTUKQNCQGC4`) for one of the offered lock
   periods (30 / 90 / 180 days), which routes it into the DeFindex vault
   (`CB2U6PWS225PXWOAYGFIAWXYJBQHBWBQHEPC6NU2M257DKBRLBGMUPUZ`).

Contract behaviour on this path is documented in [`../architecture.md`](../architecture.md);
the addresses are listed in [`3.2-mainnet-deployment-and-live-yields.md`](./3.2-mainnet-deployment-and-live-yields.md).

## 3. KYC

The KYC is **Anclap's**, not Vaquita's. SEP-24 hands the user to the anchor's hosted
interactive flow, which collects and verifies identity data under Anclap's own compliance
programme, and it is served in Spanish. Vaquita neither collects nor stores KYC data, and
the outcomes the anchor returns — document refused, limit exceeded, session expired,
provider unavailable — surface as handled messages in the app rather than dead ends.
