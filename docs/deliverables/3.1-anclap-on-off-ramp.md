## 2. What the flow consists of

The deliverable spans four legs. C1 is only satisfied by a recording that shows all four
without a cut.

1. **Fiat in.** The user funds an Anclap account in ARS (or USD) and initiates a SEP-24
   interactive deposit from the Vaquita web app.
2. **KYC.** Anclap's SEP-24 interactive flow collects identity data. It is the
   provider's own flow, opened from the Vaquita app, and **it is already served in
   Spanish** — the criterion is met by the integration itself rather than by work on our
   side. What Vaquita owns on this leg is the handling of the outcomes: a rejection
   (document refused, limit exceeded, session expired, provider unavailable) must surface
   a handled message in the app rather than a dead end.
3. **Settlement to USDC.** Anclap settles to USDC on the Stellar public network, issued
   by Circle (`GA5ZSEJYB37JRC5AVCIA5MOP4RHTM335X2KGX3IHOJAPP5RE34K4KZVN`).
4. **Deposit into the vault.** The user deposits that USDC into `vaquita-pool`
   (`CDTTAZ3NK4MMDHK2C3I6LRDT4YADJZ2QXINKLKQNZUVX7OTUKQNCQGC4`) for one of the offered
   lock periods (30 / 90 / 180 days), which routes it into the DeFindex vault
   (`CB2U6PWS225PXWOAYGFIAWXYJBQHBWBQHEPC6NU2M257DKBRLBGMUPUZ`). Contract behaviour on
   this path is documented in [`../architecture.md`](../architecture.md).

The addresses above are already live; see
[`3.2-mainnet-deployment-and-live-yields.md`](./3.2-mainnet-deployment-and-live-yields.md).
What is unproven is the ramp leg (1–2) and its junction with leg 4.

## 3. KYC and error handling

The KYC is **Anclap's**, not Vaquita's. SEP-24 hands the user to the anchor's hosted
interactive flow, which collects and verifies identity data under Anclap's own compliance
programme and is served in Spanish. Vaquita neither collects nor stores KYC data. The
criterion *"KYC functional in Spanish"* is therefore satisfied by the anchor, and the
recording is what shows a reviewer that it is.

What remains on the Vaquita side of the boundary is C4: every state the anchor can hand
back has to end somewhere the user understands. The transaction error-mapping helper that
covers the on-chain paths is documented in
[`3.3-full-ux-readiness.md`](./3.3-full-ux-readiness.md); the ramp states should be listed
the same way, with the message each one produces.
