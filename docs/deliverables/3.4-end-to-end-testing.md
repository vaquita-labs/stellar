## 2. Test pyramid

The full strategy is [`../testing.md`](../testing.md); the requirement → artifact map is
[`../qa/e2e-coverage-map.md`](../qa/e2e-coverage-map.md). Each layer only tests what the
layer below cannot: contract arithmetic is not re-tested in e2e, and wallet popups are not
tested in Playwright.

| Layer | What it proves | Network | Scale |
|---|---|---|---|
| Rust contract tests | Deposit/withdraw accounting, early-withdraw fee, randomised solvency invariant, soulbound mint with backend signature, pause and timelocked upgrade, one regression per security finding | in-process Soroban env | 169 tests, ≥ 80 % line coverage enforced |
| Vitest unit (web) | Soroban tx builders, deposit-id computation, vault/Blend query parsing, tx-error humanisation, badge error mapping, feature flags | none | 101 tests |
| Vitest unit (api + shared) | Badge and leaderboard services, config readiness, shared helpers | none | 132 tests |
| Integration | The frontend's contract clients against the deployed testnet contracts | testnet | 10 tests |
| Playwright e2e | User flows through the real UI, wallet signing stubbed at the Pollar adapter | testnet | 14 tests |
| Manual wallet regression | Real wallet UIs, browsers, reject / wrong-network paths, session restore | testnet | see §5 |

## 3. Automated end-to-end suite (C1)

`apps/web/e2e/`, run with `pnpm --filter @vaquita/web test:e2e`. Each flow named in the
criteria maps to one spec file:

| Flow named in the criteria | Spec |
|---|---|
| Onboarding | `apps/web/e2e/onboarding.spec.ts` |
| Deposits | `apps/web/e2e/deposit.spec.ts` |
| Withdrawals (matured + early) | `apps/web/e2e/withdraw.spec.ts` |
| Leaderboard interactions | `apps/web/e2e/leaderboard.spec.ts` |
| NFT badge interactions (claim + mint) | `apps/web/e2e/badges.spec.ts` |

Wallet signing is stubbed at the Pollar adapter boundary, so no extension is needed and the
suite is deterministic in CI. Real wallet UIs are covered by the manual matrix in §5.

**Workflow:** `.github/workflows/e2e.yml` — PRs touching `apps/web/**`, a nightly schedule,
and manual dispatch. Artifacts: `playwright-report` (HTML + traces on failure) and
`e2e-results` (JUnit + JSON).

## 4. Integration tests (C2)

`apps/web/src/networks/stellar/__integration__/`, run with
`pnpm --filter @vaquita/web test:integration` against the **deployed testnet contracts**:
`compute_deposit_id`, `deposit`, `withdraw`, `get_position`, `mint_badge` with a claim
signed by the API, and the SEP-10-style session against the API.

Contract addresses are read from `GET /api/v1/config`, never hardcoded, because testnet
resets move the Blend and DeFindex addresses. Secrets come from the environment.

**Workflow:** `.github/workflows/integration-tests.yml` — PRs touching
`apps/web/src/networks/**` or `contracts/**`, plus manual dispatch. Artifact
`integration-junit`.

**Entry methods exercised:** Freighter, xBull and Rabet as external wallets, plus the
Pollar social login as the control for the custodial branch. Each ran the sign-off case
set — connect and session restore, locked deposit, early withdrawal, leaderboard, and
soulbound badge mint — with the on-chain transaction recorded for every money-path case.
`W-06` (withdrawal at maturity) was additionally exercised on an aged position and passed,
covering the one case the 7-day testnet lock period normally puts out of reach.

**Two wallets could not be reached**, both for reasons outside the application and outside
Vaquita's control:

- **Albedo** — `albedo.link` stopped answering on TCP 443 during the run while DNS
  resolved and the Cloudflare edge was reachable. The popup renders blank, so nothing
  about the app was exercised. Recorded **BLOCKED** rather than FAIL, and excluded from
  the rate. A funded account is standing by for the re-run.
- **Hana** — the current build marks Stellar as `INELIGIBLE` in its network list, so the
  wallet never exposes a Stellar account. Recorded **N/A**.
