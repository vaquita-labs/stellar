## 3. Automated end-to-end suite (C1)

`apps/web/e2e/`, run with `pnpm --filter @vaquita/web test:e2e`. Each criterion flow maps
to one spec file:

| Flow named in the criteria | Spec | Specs |
|---|---|---|
| Onboarding | `apps/web/e2e/onboarding.spec.ts` | 3 |
| Deposits | `apps/web/e2e/deposit.spec.ts` | 2 |
| Withdrawals (matured + early) | `apps/web/e2e/withdraw.spec.ts` | 2 |
| Leaderboard interactions | `apps/web/e2e/leaderboard.spec.ts` | 3 |
| NFT badge interactions (claim + mint) | `apps/web/e2e/badges.spec.ts` | 2 |

Wallet signing is stubbed at the Pollar adapter boundary, so no extension is needed and
the suite is deterministic in CI. What that stub cannot cover — the real extension UI, its
network selector, its reject button — is exactly what the manual matrix in §5 exists for.

**Workflow:** `.github/workflows/e2e.yml` — PRs touching `apps/web/**`, a nightly
schedule, and manual dispatch. It builds with `E2E_TEST_SIGNER=1` and runs the chromium
project. Artifacts: `playwright-report` (HTML + traces on failure) and `e2e-results`
(JUnit + JSON); the Step Summary carries passed/total.

## 4. Integration tests (C2)

`apps/web/src/networks/stellar/__integration__/`, run with
`pnpm --filter @vaquita/web test:integration` against the **deployed testnet contracts**:
`compute_deposit_id`, `deposit`, `withdraw`, `get_position`, `mint_badge` with a claim
signed by the API, and the SEP-10-style session against the API.

Contract addresses are read from `GET /api/v1/config`, never hardcoded, because testnet
resets move the Blend and DeFindex addresses. Secrets come from the environment; the CI
run uses the `INTEGRATION_STELLAR_SECRET` repository secret.

**Workflow:** `.github/workflows/integration-tests.yml` — PRs touching
`apps/web/src/networks/**` or `contracts/**`, plus manual dispatch. Artifact
`integration-junit`; Step Summary with passed/total.

| `.github/workflows/api-ci.yml` | PR on `apps/api/**`, `packages/**` | `api-vitest-junit`; per-package pass/fail table on the job summary |

**How the rate is computed** ([`../testing.md`](../testing.md) §3):

- Automated: `passed ÷ total` from the `e2e.yml` and `integration-tests.yml` Step
  Summaries on the submitted commit. A flaky retry counts once, by final status.
- Manual: `PASS ÷ (PASS + FAIL)` from the wallet matrix tally, `N/A` excluded.
- Contract and unit suites must be 100 % green on the same commit; they do not enter the
  rate.
- A critical-flow failure blocks submission regardless of the aggregate.

## 7. Known gaps

Recorded so a reviewer sees them stated rather than discovers them. Full list in
[`../qa/e2e-coverage-map.md`](../qa/e2e-coverage-map.md) §4.

| Gap | Impact | Covered by |
|---|---|---|
| Automated e2e cannot drive real extension popups | Real wallet UI, reject button, network selector | Manual matrix |
| Testnet Blend / DeFindex addresses move on every testnet reset | Integration suite needs re-pointing | `/api/v1/config` as the single source of truth |
| Positions with a lock period > ~90 d archive before maturity | Matured withdrawal on long periods needs a TTL restore first | Not covered; latent unless such a period is configured |
| Matured withdrawal cannot be exercised manually on testnet — the shortest lock is 7 days | `W-06` | Rust contract tests and the testnet integration suite |
| Lobstr is mainnet-only | No testnet coverage for that wallet | A run against the mainnet build |
